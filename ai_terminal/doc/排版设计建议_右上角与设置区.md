# 主界面右上角 & 设置区域 — 排版设计建议

> 日期：2026-11-16
> 范围：终端主界面顶栏右侧动作区（含溢出菜单）+ 设置区域（抽屉设置分区）
> 方法：以代码为现状事实（`lib/pages/terminal_page.dart`、`lib/widgets/nav_drawer.dart`、`lib/widgets/settings_inline_panel.dart`、`lib/core/settings_catalog.dart`），以 Warp / VS Code / iTerm2 / Cursor / Claude Code 的公开设计资料和 NN/g、Apple HIG、渐进披露等研究文献为依据。

---

## 0. 结论先行（TL;DR）

当前顶栏与设置区经过前几轮收敛，**入口唯一性、就地编辑、返回路径**这三大问题已经解决，骨架是对的。剩下的问题集中在四处，按优先级：

| 优先级 | 问题 | 一句话方案 |
|---|---|---|
| **P0** | 设置区**没有搜索**（唯独这个分区没有，其它四个分区都有） | 设置分区顶部加搜索框，命中即展开对应组并高亮 |
| **P0** | 八个设置组**平铺无层次**，低频组（通知）与高频组（外观）平级 | 顶部加「常用」摘要组（只列改过的项），组序按使用频率排 |
| **P1** | ⋯ 溢出菜单的「前往」组与抽屉顶栏五标签**双入口重复** | 「前往」组砍到 2-3 条（带计数的保留），其余靠抽屉标签 |
| **P1** | 顶栏「监控」开关与底部状态条**信息重复** | 合并：状态条常驻，监控按钮改为展开详情面板 |
| **P1** | 裸图标可接受（高频工具栏豁免），但「面板已开启」状态不够醒目 + SFTP 本地页点击静默失败 | 开启态加 brandBg 胶囊底；SFTP 本地页置灰 |

**不建议动的**：42px 顶栏高度、Ctrl+K 键帽按钮、AI ✦ 图标、抽屉六边形（五标签+层级栈+就地表单）、AI 右侧面板布局——这些全部与业界收敛出的模式一致，是这套界面目前最值钱的部分。

## 1. 现状盘点（以代码为准）

### 1.1 顶栏右侧动作区

顶栏高 42px，从左到右（`terminal_page.dart:2285-2423`）：

```
[标签页列表 ……] [+]          [🔍 Ctrl K]  [🎨]  [✦]  [📁]  [📈]  [⋯]
     Expanded 吃掉剩余宽度      键帽按钮    └───── 五个 32×32 图标按钮 ─────┘
```

| 控件 | 类型 | 行为 |
|---|---|---|
| 🔍 Ctrl K | 图标+键帽文本 | 命令面板（全局搜索与跳转） |
| 🎨 调色板 | MenuAnchor 浮层 | 配色/字号就地改，浮层带终端实时预览，「更多」进设置抽屉外观组 |
| ✦ AI | 面板开关 | 切换右侧 AI 面板可见性 |
| 📁 SFTP | 面板开关 | 切换 SFTP 文件面板（仅远程标签页） |
| 📈 监控 | 面板开关 | 切换监控面板 |
| ⋯ | PopupMenu | 唯一溢出菜单 |

⋯ 菜单结构（`terminal_page.dart:2549-2597`）：

- **前往**（7 条）：主机管理 `3 台` / 快捷命令 `N 条` / 运维工作流 `N 个` / 审计日志 `今日 N 条` / 设置 `8 组` / 变更台账 / 变更窗口
- **本终端**：重新连接 / 端口转发（仅远程）/ 命令历史 / 清屏（仅移动端）
- **快捷命令**：前 5 条直通执行
- **视图**：专注模式 / 切换 AI 面板位置

### 1.2 设置区域

设置是抽屉的第五个分区（`nav_drawer.dart`）。抽屉宽 `min(600, 92%窗口宽)`，手机端（<640）占满屏。结构：

```
┌──────────────────────────────┐
│ 设置                    ✕    │
│ [主机][命令][工作流][审计][设置] │  ← 五分区标签
│ ┌ 外观  跟随系统·Dracula·14px │
│ ├ AI 模型  6 个·当前 qwen…    │  ← 八组 SettingsRowCard
│ ├ Agent  步数不限·超时 600s   │     就地展开内嵌面板
│ ├ 联网 / 安全 / MCP / 规范 / 通知│
│ └ 关于: 语言 / 诊断           │
└──────────────────────────────┘
```

关键事实：

- 八组 = `kSettingsEntries`（外观 / AI 模型 / Agent / 联网 / 安全 / MCP 服务器 / 规范 / 通知），每组折叠卡带**实时副标题读数**（如「2/2 已连接 · 8 个工具」）。
- 组间 `kSettingsGroupGap = 26`，行距 `kSettingsRowGap = 10`——上一轮刚按用户反馈放宽过。
- 展开后是同一份 `SettingsInlinePanel`，与整页设置同源，无 dialog。
- **主机/命令/工作流/审计四个分区都有搜索框，唯独设置分区没有**（`nav_drawer.dart:450/565/609/656` 各有一个 `_searchField`，`_settings()` 没有）。

## 2. 调研综述：业界怎么做的

### 2.1 终端工具

**Warp**（官方产品原则，warp.dev/blog/how-we-design-warp-our-product-philosophy）：
- “Keep the power, but fix the UI”“A great out-of-the-box experience”——默认即用，高级项渐进披露。
- 主题系统的设计取舍（warp.dev/blog/how-we-designed-themes…）：**主题 = 一个可点选的完整方案，而不是一墙独立旋钮**。“Themes are hard to control, you have to turn a ton of individual knobs”。Warp 把配色收敛成「选主题 + 一个 accent 色」，预览所见即所得。
- Terminal / Agent 双模式（docs.warp.dev）：**Agent 控件默认隐藏，进入会话才出现**，“Agent controls appear only when you're in a conversation, keeping your terminal clean otherwise”。

**VS Code**（code.visualstudio.com/blogs/2026/10/15/modern-ui，2026-10 官方复盘）：
- 现代化 UI 上线后被用户反馈打脸的核心一条：**“Overall density: Gaps and panel padding left less room for code…”**——在 1920×1080 上新版横向多占 20px、纵向多占 12-18px，用户明确说“更宽松不等于更好，如果我因此少看见代码就不是改进”。VS Code 的回应是加 `Layout Density = Compact` 而不是回滚。
- 设置编辑器二十年演化方向：**搜索永远第一**。从 v1.8 的“big Search bar”，到自然语言搜索（输入 “how to set editor font size” 也能命中），再到图形化 UI 上线时**保留并优先强化搜索**；`@modified` 筛选器专门回答「我改过什么」。
- 设置分组顶部恒置 **“Commonly Used”** 组（vscode.js.cn/docs/configure/settings）。

**iTerm2**（iterm2.com/documentation-preferences）：
- macOS 原生偏好窗口：左侧栏分类 + 右侧表单 + 顶部搜索，高级项（Advanced / 每 Profile 覆盖）渐进披露。
- 与终端相关的一个细节值得注意：**标签栏位置、状态栏位置都是设置项**——状态条在 iTerm2 里是常驻信息层，而不是一个要开关的“面板”。

### 2.2 Agent 软件

**行业收敛出的三个模式**（jacar.es “UI design for agents”、labhub AI-Native UI 2025 指南、gunbark.dev 模式库）：

1. **进度面板模式**：对话列 + 独立任务状态列分离，Claude Code / Cursor / Cline / Aider 四家几乎同形收敛，“The convergence suggests the pattern works”。每一步可折叠、可审计。
2. **审查-批准界面**：副作用操作前用领域语义展示（diff / 表格 / 预览），批准从盲点按钮变成知情决策。
3. **双表面分工**（Editor vs Manager）：并发 agent ≥1 时才值得有管理面板；低于这个并发量，“the Manager Surface adds overhead”。

**关于 AI 入口的放置**，2025 年主流形态就是本 app 这种：**编辑器/终端 + 右侧 AI 面板（composer + chat）**，Cursor、Cline、Copilot Chat 全部同构；模型选择器放在**输入框旁边**而不是顶栏（Warp 的 toolbelt、Cursor 的 composer、本 app AI 面板底部的模型胶囊都如此）。✦（sparkle）图标已成为「AI」的跨产品通用符号（Copilot / Gemini / Cursor 全用）。

### 2.3 通用 UX 研究

**图标可用性**（NN/g, nngroup.com/articles/icon-usability、Top 10 Application-Design Mistakes #5）：
- 75 个电商/内容图标测试，**只有 6 个识别率超 80%**；home、print、搜索放大镜是仅有的“近乎通用”图标。
- 齿轮、信封这类“设计师以为通用”的图标，无文字时依然大量被误解；tooltip 不算标签（触屏没有 hover）。
- 例外条款：**“Repeated actions in a dense toolbar used daily — Acceptable once users have learned them”**——高频天天用的工具栏图标，学会后可以裸奔。

**渐进披露**（NN/g 2006；IxDF；Apple HIG）：
- 对复杂表单/设置页，渐进披露让首次任务完成时间**降低 20-40%**。
- 反面警告同样重要：**“Avoid multiple access paths. Users can become confused if they can reach the same information or feature in several ways.”**（IxDF）——同一信息多条路径会制造困惑。
- 一级菜单/选项组控制在 **4-7 项**；超过就分组或收进“更多”。
- “高级”功能如果变成每日任务，渐进披露反而变成 hindrance（menu diving）。

**Apple HIG**（WWDC 2025 Get to know the new design system）：
- 嵌套容器圆角要 concentric（内圆角 = 外圆角 − 内边距）；密集桌面环境用圆角矩形、胶囊只留给突出动作。
- macOS 密度哲学：inspector 类高密度面板继续用小控件，不因“现代化”牺牲信息密度。

## 3. 诊断：现状 vs 依据

### D1. 设置区没有搜索 —— 与所有参照系相反（P0）

八组设置里散着约 60+ 个可选项。用户心智是「我要改超时时间」，路径却是：开抽屉 → 猜「超时」在哪组 → 展开 Agent 组 → 滚动找。VS Code 用二十年把「搜索第一」做成了设置页的事实标准，macOS 系统设置、iTerm2 偏好窗口全都有搜索框。**而本 app 的设置分区是抽屉五个分区里唯一没有搜索框的**——主机能搜 IP、审计能搜命令，设置反而不能搜“超时”。这是全案里依据最硬、成本最低的一条。

### D2. 八组平铺，无「常用」概念 —— 频率错位（P0）

组序是功能分类序（外观→AI→Agent→联网→安全→MCP→规范→通知），不是使用频率序。「通知-未开启」这种大多数用户永不触碰的组，与「外观」平级占据首屏。VS Code 的答案是恒置 **Commonly Used** 组 + `@modified` 筛选；渐进披露的 4±1 工作记忆限制（Cowan 2001）也支持「首屏只给一个被筛选过的小集合，而不是全量目录」。

副标题读数是现状的一个亮点（等于自带状态摘要），但它只回答了「这组现在什么状态」，没回答「我上次改了什么、我该改哪个」。

### D3. 「前往」组双入口 —— 多条路径（P1）

⋯ 菜单「前往」组的五条抽屉入口，与抽屉顶部五标签是**同一批目的地的第二套入口**；再加上命令面板 Ctrl+K 里还有一套（分组名“抽屉”），同一目的地最多**三条路径**。IxDF 明确警告 multiple access paths。

但要公平：⋯ 目前同时承担「开抽屉的唯一鼠标入口」和「目的地清单」两个角色，直接砍掉「前往」组会让鼠标用户失去发现性。且现状的 trailing 计数（`3 台`、`今日 60 条`）是不错的数据密度。结论应是**减脂**而不是截肢：⋯ 保留 2-3 条高频（且**只保留能显示计数的**，让菜单行本身携带状态），台账/变更窗口这类整页跳转保留；其余靠抽屉标签——抽屉打开后标签就在眼前，菜单里再列一遍是纯冗余。

### D4. 「监控」开关 vs 底部状态条 —— 同一信息两个容器（P1）

实拍确认底部状态条常驻显示 CPU / 内存 / 上传 / 下载 / 磁盘 / 开机时长；顶栏 📈 又开关一个监控面板。iTerm2 的模式是状态条 = 常驻轻量信息 + 设置里控制内容，**不存在“开关一次状态条”这个动作**；VS Code 状态栏同理。两个容器展示同源数据，用户要自己推断「开关的和常驻的有什么区别」。方案二选一：要么监控面板只放状态条放不下的重内容（进程列表/网络曲线）并在 tooltip 里说清楚，要么直接砍掉面板留状态条。

### D5. 四个裸图标的语义风险 —— 有依据的担忧，但不是全案（P1）

🎨 / 📁 / 📈 / ⋯ 都不在 NN/g 那「6 个 80%+ 识别率」名单里，📁 尤其暧昧（文件管理？SFTP？上传？）。但同一份 NN/g 研究也给了豁免条款：**每日高频使用的密集工具栏，图标学会后可接受**；本 app 顶栏正是这种场景，且每个按钮都有 tooltip、AI 的 ✦ 已是行业通用符号、按钮有激活态着色。强行加文字标签会把 5×32px 的动作区推到 260px+，挤压标签区——VS Code 的教训（每个像素都会跟用户的工作内容抢）在这里同样成立。
**所以问题不是“图标要换成文字”，而是：** (a) 裸图标被学会的前提是「状态可读」——现状 `_buildTopAct` 已统一为「开启 = 图标染 brand 色」（五个按钮共用同一组件，一致性没问题），但仅 12px 的图标变色在 42px 深色顶栏上对比弱，可加 brandBg 胶囊底强化开/关差异；(b) SFTP 在本地标签页点击无反应——静默失败比图标歧义更伤（`_toggleSftpPanel` 对 `tab.isLocal` 直接 return，虽然 `_buildTopAct` 支持 `onTap == null` 置灰，但当前调用点没有传 null），应置灰并把 tooltip 改成「仅远程会话」；(c) ⋯ 菜单里的「快捷命令直通前 5 条」与抽屉命令分区、Ctrl+K 也可考虑合并。

### D6. 设置抽屉 600px 对重面板略窄（P2）

外观组（主题卡片+字号滑杆）、AI 组（模型列表+端点表单）是最重的两组。Warp 主题编辑、VS Code 设置页都给了 ≥720px 的编辑宽度。600px 下模型行的「名称 + 状态 + 端点」三段已经开始截断（实拍确认副标题读数有 ellipsis）。可选方案：设置分区的抽屉宽度独立放宽到 ~680，或重面板（端点编辑）用层级栈下钻全屏宽。手机端已满屏，不受影响。

### D7. 顶栏密度本身是对的（勿动）

42px 顶栏、32px 控件、动作组贴右缘——介于 VS Code（~35px 标题栏）与 Warp 之间，恰好避开 VS Code 翻车的“宽松化抢空间”问题；Warp 的“输入位置”之争也证明终端用户对**垂直空间**极其敏感，42px 不要为了“透气”加高。

## 4. 建议清单（按优先级）

### P0-1 设置分区加搜索

- 位置：设置分区第一个控件（与其余四个分区的 `_searchField` 同位同款，提示文案「搜索设置项」）。
- 行为：输入即过滤八组的**标题 + 组内选项文案**（`SettingsInlinePanel` 各组的字段标签已在代码里，可静态建索引）；命中的组自动展开并滚动定位、命中项高亮底色；清空恢复折叠序。
- 无命中给一条空态：「没有叫“XX”的设置 · 按 Ctrl+K 试试」——空态指路，符合本项目文案纪律。
- 依据：VS Code 设置搜索（v1.8 → 自然语言搜索 → UI 版保留搜索）、macOS 系统设置、IxDF 渐进披露「设置页还应提供搜索，当用户知道要改什么却找不到入口时，搜索比层级导航更高效」。

### P0-2 「常用」摘要组 + 组序按频率

- 八组之上新增一个 **「已修改」摘要区**：只列与默认值不同的项（外观主题、AI 当前模型、Agent 超时…），一行一项，点击直达该组展开位置。全部为默认值时不渲染该区域（零占位）。
- 组序调整为：外观 → AI 模型 → Agent → 安全 → MCP 服务器 → 联网 → 规范 → 通知（安全提到 MCP 前：高危确认是运维用户第一周就要碰的，MCP 是第二个月的）。
- 依据：VS Code “Commonly Used” + `@modified`；Cowan 4±1；「一级组 4-7 项」规则（8 组压线，摘要区把首屏决策集缩到 <4）。

### P1-1 ⋯ 菜单「前往」组减脂

- 保留：主机管理（计数）、审计日志（今日计数）、设置（组数）——三行都带状态读数，菜单即仪表盘。
- 移出：快捷命令、运维工作流（其内容已经以「快捷命令直通」和面板入口出现过；抽屉标签一键可达）；变更台账/窗口保留（它们是整页，抽屉里没有）。
- 预期效果：⋯ 菜单从 7 条组缩到 5 条组，「本终端」「视图」组上移一屏内可见。
- 依据：IxDF 单一分层原则；NN/g 菜单 4-7 项。

### P1-2 监控职责重划

- 监控面板内容改为状态条的**超集**（进程 top、网速曲线、磁盘 IO），tooltip 改为「资源详情」；或激进方案：删面板、状态条可点击展开一个就地详情浮层。
- 同步给 SFTP 按钮在本地标签页置灰（tooltip 说明「仅远程会话」），消灭静默失败。

### P1-3 顶栏按钮状态语言强化

- 五个按钮已共用 `_buildTopAct`（已核对），「开启 = brand 色」这条规则已成立；缺的是**强度**：仅图标染色，42px 深色顶栏上不易察觉。建议面板开启时追加 `tc.brandBg` 胶囊底 + brand 图标；临时菜单（🎨）展开时只给胶囊底不给染色，把「持久状态」和「瞬时展开」区分开。
- 依据：Apple HIG「一个图标一个含义、一套风格」；激活态一致性比加标签便宜。

### P2 两项观察

- 设置分区抽屉宽度 600 → 720（或重面板下钻全屏宽），解决模型行截断。
- 若未来引入多 agent 并发（编排模式已有雏形），参考 Claude Code agent view 的「按注意力分组的任务行」做 Manager 视图；**并发 <2 之前不要做**（gunbark：低于阈值 Manager Surface 是 overhead）。

## 5. 明确不建议改的

| 现状 | 为什么是对的 |
|---|---|
| 42px 顶栏 / 32px 控件 | 处于 VS Code(35) 与 Warp(~40) 的业界带内；垂直空间是终端用户最敏感的资源（Warp“输入位置”之争、VS Code 密度复盘） |
| Ctrl K 键帽按钮 | 唯一带文字的入口，与 Linear/Raycast 惯例一致；放大镜是幸存的通用图标 |
| ✦ 作为 AI 图标 | 2025 后已是跨产品通用符号（Copilot/Gemini/Cursor/Warp） |
| AI 右侧面板 + 面板开关 | “composer + chat side panel”是 Cursor/Cline/Copilot 收敛出的主流形态；模型胶囊在输入框旁，同 Warp toolbelt |
| 抽屉五标签 + 层级栈 + 就地表单 | 上一轮刚解决的单一载体问题，与渐进披露「单一层二级界面足够」一致，不要再动 |
| 调色板浮层带终端实时预览 | 正面命中 Warp 主题设计的全部三原则（所见即所得、少旋钮、一键切换） |
