## 2. R1 · 设置分区搜索

### 2.1 需求描述

抽屉「设置」分区顶部增加搜索框，与其余四个分区（主机/命令/工作流/审计）的搜索框**同位、同款、同交互**。输入即过滤设置项，命中的组自动展开并滚到视野内。

### 2.2 现状

`nav_drawer.dart` 中 `_hosts/_snippets/_runbooks/_audit` 各调用一次 `_searchField(tc, hint)`（:450/565/609/656），`_settings(tc)`（:751）**没有调用**。`_query`（:783）与 `_filter<T>`（:785）是通用件，设置分区可直接复用。

### 2.3 交互规格

| 项 | 规格 |
|---|---|
| 位置 | `_settings()` 返回的 ListView 第一项，在八个 `SettingsRowCard` 之前 |
| 提示文案 | 中文「搜索设置项」/ 英文 `Search settings` |
| 高度 | 36（与其它分区一致） |
| 过滤对象 | 组标题 + 组内所有可见选项标签（见 2.4 索引表） |
| 命中行为 | 命中的组**强制展开**（不看 `_expanded`），未命中的组隐藏 |
| 空查询 | 恢复原状：按 `_expanded` 决定展开态，八组全显 |
| 无命中 | 显示空态文案「没有叫“{query}”的设置」+ 副行「按 Ctrl+K 可以搜命令和主机」 |
| 清空按钮 | 查询非空时搜索框尾部出现 ✕，点击清空并恢复 |
| 「关于」区 | 查询非空时隐藏（语言/诊断不属于设置项语义，避免搜“语言”命中噪音） |

### 2.4 索引表（实现用）

搜索匹配的键集合，按组定义。粗体为组标题，其余为组内选项标签（取自 `settings_inline_panel.dart` 的 `_label` 调用）。

| 组 id | 可搜关键词 |
|---|---|
| `appearance` | **外观** 主题模式 深色 浅色 跟随系统 终端配色 配色 主题 字号 字体大小 回滚缓冲 缓冲行数 自动会话日志 终端快捷键 快捷键 |
| `ai` | **AI 模型** 模型 当前使用的模型 端点 接口地址 API Key 添加端点 编辑端点 |
| `agent` | **Agent** 最大执行步数 步数 单步响应超时 超时 命令超时倍数 自定义提示词 提示词 |
| `web_search` | **联网搜索** 联网 搜索 允许 AI 联网搜索 后端 返回条数 |
| `security` | **安全** 应用锁 生物识别 面容 指纹 凭据存储 高危命令 二次确认 清除本机数据 |
| `mcp` | **MCP 服务器** MCP 服务器 启用 MCP 添加服务器 工具 |
| `knowledge_rules` | **内部规范** 规范 规则 添加规则 |
| `notification` | **通知** 任务完成提醒 提醒 什么时候提醒 Webhook 地址 |

### 2.5 实现要点

1. 在 `NavDrawer` 中新增静态索引：
   ```dart
   /// 设置搜索索引：组 id → 可匹配的文本集合。
   /// 新增设置项时同步"往这里加词"，否则搜索命中不了它。
   static const Map<String, List<String>> kSettingsSearchIndex = { ... };
   ```
   位置放在 `nav_drawer.dart` 内、`NavDrawer` 类中，与 `shortTitles` 并列。

2. 匹配函数：
   ```dart
   bool _settingsGroupMatches(String id) {
     if (_query.isEmpty) return true;
     final hay = [id, ...?NavDrawer.kSettingsSearchIndex[id]]
         .join(' ').toLowerCase();
     return hay.contains(_query);
   }
   ```
   注意同时匹配 `id`（英文 id 让英文用户能搜 `mcp`、`agent`）。

3. `_settings()` 改造：
   ```dart
   Widget _settings(ThemeColors tc) {
     final query = _query;
     final matched = kSettingsEntries
         .where((e) => _settingsGroupMatches(e.id))
         .toList();
     return _list([
       _searchField(tc, UiText.t('搜索设置项', 'Search settings')),
       const SizedBox(height: kSettingsGroupGap - kSettingsRowGap),
       if (query.isEmpty) ...原有的八组渲染（按 _expanded 决定展开）
       else if (matched.isEmpty) 空态
       else ...matched 每组强制 expanded: true,
       if (query.isEmpty) ...[
         SettingsSectionLabel(UiText.t('关于', 'About')),
         const SettingsAboutRows(),
       ],
     ]);
   }
   ```

4. **键盘可达性**：抽屉 `initState` 里 `_focusForLevel()` 目前只在主机分区请求搜索框焦点（:164）。设置分区**不要**自动聚焦搜索框——用户进设置多数是来点开关的，抢焦点会让 Esc 行为变怪。保持 `_closeNode` 聚焦。

### 2.6 验收标准

- [ ] 设置分区可见搜索框，样式与其余四分区一致（36 高、surface 底、brand 聚焦描边）
- [ ] 输入「超时」→ 只剩「Agent」组，且已展开，能看到「单步响应超时」
- [ ] 输入「主题」→ 只剩「外观」组，已展开
- [ ] 输入「MCP」→ 只剩「MCP 服务器」组（大小写不敏感）
- [ ] 输入「zzz」→ 空态文案出现，八组与「关于」都不显示
- [ ] 清空 → 八组按原 `_expanded` 状态恢复，「关于」回归
- [ ] 查询非空时「关于」区隐藏
- [ ] 手机 360 宽下不溢出（`tester.takeException()` 为 null）

## 3. R2 · 设置组频率排序 + 已修改摘要

### 3.1 需求描述

调整 `kSettingsEntries` 的组序，使其反映「上手顺序」而非「功能分类」；并在八组之上增加一个「已修改」摘要区，只列出与默认值不同的项，一行一项、点击直达。

### 3.2 组序调整

现状：外观 → AI模型 → Agent → 联网搜索 → 安全 → MCP → 内部规范 → 通知

目标：外观 → AI模型 → Agent → **安全** → **MCP** → **联网搜索** → 内部规范 → 通知

理由：安全（应用锁、高危命令确认）是运维用户第一周就会碰的；联网搜索与内部规范是「让 AI 更懂我」的调优项，属于第二阶段的优化；MCP 是能力扩展，早于调优。

### 3.3 「已修改」摘要区规格

| 项 | 规格 |
|---|---|
| 显示条件 | 至少一项与默认值不同时显示；全默认时整块不渲染（零占位） |
| 位置 | 搜索框之下、八组之上 |
| 区块标题 | `已修改` / `Changed`（用现有 `SettingsSectionLabel`） |
| 每行内容 | 左：设置项名称（如「主题模式」）；右：当前值（如「深色」）；行高 36 |
| 行点击 | 滚动到对应组并展开，不关闭抽屉 |
| 最大行数 | 6 行；超出显示「还有 N 项」，点击后展开全部 |
| 最多覆盖的键 | 见 3.4 |

### 3.4 纳入摘要的设置键与默认值

| 键 | 名称 | 默认值 | 当前值展示 |
|---|---|---|---|
| `themeMode` | 主题模式 | `dark` | 深色/浅色/跟随系统 |
| `terminalPalette` | 终端配色 | `kDefaultTerminalPalette` | 配色显示名 |
| `terminalFontSize` | 字号 | `13` | `14px` |
| `aiSelectedModelId` | 当前模型 | `null`（空） | 模型名 |
| `agentMaxSteps` | 最大执行步数 | `0`（不限） | `不限` 或 `N 步` |
| `agentAiTimeoutSeconds` | 单步响应超时 | `120` | `120s` |
| `appLockEnabled` | 应用锁 | `false` | `已开启` |
| `mcpEnabled` | 启用 MCP | `false` | `已开启` |

> 键名以代码实际使用为准，实现前用 `grep -n "SettingsDao.set('" lib/` 全量核对一遍，表里缺的键不纳入（宁可少列，不要列一个永远读不到默认值的键）。

### 3.5 实现要点

- 摘要区放在 `nav_drawer.dart::_settings()`，与 R1 一起改，避免两次重排。
- 新增私有方法 `List<_ChangedRow> _changedSettings()`，返回 `(label, value, groupId)` 三元组列表；空列表 = 不渲染。
- 点击行 → `_toggle(groupId)`（若已展开则不动）+ 用 `Scrollable.ensureVisible` 滚到该 `SettingsRowCard`。需要给每张卡加 `GlobalKey`（`Map<String, GlobalKey>`，在 `_settings()` 内按需创建，不放进全局状态）。

### 3.6 验收标准

- [ ] 新装状态（全默认）→ 设置分区**没有**「已修改」区
- [ ] 改字号 13→16 → 出现「已修改」区，含「字号 16px」一行
- [ ] 点该行 → 外观组展开且滚入视野
- [ ] 把字号改回 13 → 该行消失；若已无其它改动，「已修改」区整块消失
- [ ] 组序为：外观 / AI 模型 / Agent / 安全 / MCP 服务器 / 联网搜索 / 内部规范 / 通知

## 5. R4 · 设置抽屉宽度分级

### 5.1 需求描述

设置分区（尤其 AI 端点编辑、外观配色卡）在 600px 下出现文本截断。给设置分区单独放宽到 720px 上限，其余分区保持 600。

### 5.2 规格

```dart
// 当前（:271-273），所有分区共用
final width = c.maxWidth < 640
    ? c.maxWidth
    : (c.maxWidth * 0.92).clamp(0.0, 600.0);

// 目标
final maxW = _level.section == NavDrawer.sectionSettings ? 720.0 : 600.0;
final width = c.maxWidth < 640
    ? c.maxWidth
    : (c.maxWidth * 0.92).clamp(0.0, maxW);
```

### 5.3 风险与对策

- **切分区时宽度跳变**（600 ↔ 720）会晃眼。对策：给 `Container` 包 `AnimatedContainer(duration: animFast, width: width)`，让切换有一次 150ms 的过渡，而不是硬跳。
- **1600 宽窗口下 720 是否会挤压终端**：抽屉是覆盖层（`showGeneralDialog` + `Align.centerRight`），不参与布局，终端尺寸不变——不会挤压。
- **手机端不受影响**（<640 走满屏分支）。

### 5.4 验收标准

- [ ] 设置分区抽屉宽 720（1600 宽窗口下）
- [ ] 主机/命令/工作流/审计分区仍为 600
- [ ] 切换分区时宽度有过渡动画，不硬跳
- [ ] AI 组展开后端点行的名称不被截断
- [ ] 360 宽下仍是满屏

## 6. R5 · SFTP 置灰态 tooltip 说明

### 6.2 规格

```dart
tooltip: !canShow
    ? UiText.t('SFTP 仅远程会话可用', 'SFTP available on remote sessions only')
    : on
        ? UiText.t('关闭 SFTP 面板', 'Close SFTP panel')
        : UiText.t('SFTP 文件面板', 'SFTP file panel'),
```

顺带去掉「（与 AI 正交）」——那是设计意图说明，用户不需要知道布局算法。

- [ ] 本地标签页 hover SFTP → tooltip 为「SFTP 仅远程会话可用」
- [ ] 远程未开 SFTP → tooltip「SFTP 文件面板」
- [ ] 远程已开 SFTP → tooltip「关闭 SFTP 面板」

## 7. R6 · 顶栏激活态对比强化（可选）

### 7.1 需求描述

`_buildTopAct` 激活态已是 `brandBg` + `border` + `brand` 图标，但可选强化对比：目前 `border` 用的是 `tc.border`（普通描边色），与 `brandBg` 底对比弱。

### 7.2 规格（仅一行改动）

```dart
border: Border.all(
  color: active ? tc.brand : Colors.transparent,
  width: 1,
),
```

### 7.3 风险

`brand` 描边 + `brandBg` 底 + `brand` 图标 = 整块发亮，可能过重。**实现时给两个变体截图对比**（细节见 §9 验证），由效果决定是否保留。默认先只改 `border` 颜色，若视觉过重则回退为现状。

### 7.4 验收标准

- [ ] AI 面板开启时，✦ 按钮可一眼识别为「已开」（对比关闭态明显）
- [ ] 五个按钮的开启态视觉完全一致
- [ ] 不产生「整条顶栏都在发光」的廉价感

## 10. 明确不做
