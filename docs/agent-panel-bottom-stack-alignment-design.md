# Agent 面板底部区对齐参考界面 — 差距盘点与分期

参考图：Qoder Desktop 自身界面（附件 `43b06a00-...png`）。用户要求"按照这个参考一下，该补齐的补齐"。

本文只做两件事：① 把参考图拆成可核对的界面要素，逐条对着**当前代码**标注差距；② 定下分期与取舍。**所有"现状"均以符号名定位并读过代码，不是推测。**

## 1. 参考图的要素拆解

从上到下（输入框是分隔线）：

- **A 状态行**：`深度求索中，用时 17分58秒 …`（阶段 + 墙钟耗时，单独一行，强调色）
- **B 执行清单卡**：`☰ 任务 6 已完成 · 1 进行中 ⌄` 头部 + 步骤列表（绿点=完成、空心=待办），**卡内独立滚动**（右侧滚动条，首行被滚出视野）
- **C 目标行**：`🎯 进行中的目标 按照文档开始做` + 右侧三个图标（暂停 / 编辑 / 删除）
- **D 输入框**：`+` · placeholder `发消息或创建任务，/ 调用指令，@ 文件或对话` · `⊘ 完全权限 ⌄` · 模型胶囊 `DeepSeek-V4.1-Flash-1017 Default ⌄` · 圆形停止/发送键
- **E 底部状态条**（在输入框**之下**，贴着窗口底边）：`⟳ 11 轮 418 步 · 190 tok/s` `🗄 67.6M tok · 缓存命中 67%` `⭕ 28%`

## 4. 取舍（产品决定由我下，理由写清）

### 4.1 指标带下移不等于"运行条搬走"

`LiveOperationBar` 现在同时承担**控制**（暂停/恢复/停止/在终端打开）和**计量**（轮/tok/速率/环）。参考图把这两件事分在 D 的两侧：控制贴着输入框，计量在窗口底边。

决定：**拆**。控制与阶段留在输入框上方（B/C 区），计量（`buildMetricItems` 那一套）统一交给输入框下方的一条 `AgentMetricsBar`，运行中与终态共用同一条 —— 现在已经是"两者按状态互斥、同一位置"，下移后这个性质保留。好处：任务跑完数字不再换位置，用户视线不用来回找。

### 4.2 不做"把 6 个工具栏按钮塞进输入框"

参考图的输入行只有 `+`/权限/模型，因为它的功能就这些。我们的日志、历史、Runbook、联网、编排是这台产品自己的核心入口，收进胶囊会丢可见性，塞进输入行会让输入行变成第二个工具栏。

决定：工具栏**保留原样**；只把"权限/模式"这一类**状态**做成输入行内的文字胶囊（只读模式 → `只读模式`，否则 `完全执行`），模型选择保持工具栏不动。`+` 附件按钮不做 —— 本项目的输入是命令与服务器上下文，没有文件附件语义，凭空加一个按钮是装饰。

### 4.3 不复制"深度求索中"这一行

参考图那行是"当前阶段 + 已用时"。我们的运行条已经显示阶段与计时，只是形状是卡片不是裸行。再叠一行会出现两条都在说"跑到哪了"的重复信息。

决定：运行条**瘦身成一行状态**（点 + 阶段 + 用时 + 计划进度 `6/7`），控制按钮留在同一行右侧；不再在卡里重复目标全文（目标已经在 C 行的目标横幅上，两处各写一遍是浪费纵向空间）。

### 4.4 纵向空间预算

右侧面板默认比例 0.4（≈550px 宽），纵向本来紧张。B（清单，限高 168px 内部滚动）+ C（目标行 ~34px）+ 状态行 ~26px 三者叠加最多约 230px，会把会话区压掉这么多。

决定：B **只在有计划且任务处于运行/暂停/待确认时贴底**；进入终态后清单回到会话流原位（终态下"我现在在哪"不再需要锚点，历史回看更重要）。这条是参考图没有但本项目必须有的差别 —— 参考图是全屏 IDE 面板，我们是嵌在终端旁边的窄面板。

## 6. 二次逻辑验证（对照代码的挑战，实施前）

| # | 本文假设 | 查证结果 |
|---|---|---|
| V1 | 指标带下移只是改 Column 顺序 | **不成立**。`_buildBottomBar` 的 Column 里输入框是最后一项，且整个底部条有 `border(top:)`；把指标带放输入框之后需要重排 padding，否则分隔线会切在指标带与输入框之间。→ P0 连同 padding 一起改 |
| V2 | `task.stepIndex` 就是"步" | **部分成立**。参考图 `418 步` 是**累计命令/工具执行数**，而 `stepIndex` 是引擎循环计数（`_currentStepCount`）。两者在"一轮循环发多条命令"时不等。→ 用 `successCount + failureCount`（真执行数），并在文案上保持"步"；实施时复核 `_currentStepCount` 的语义再定，不许两个都试 |
| V3 | 清单贴底不影响会话流 | **不成立**。`PlanPanel` 目前在 `_buildMessageContent` 内，同一份 plan 若两处都渲染会重复显示。→ 贴底渲染时，会话流内那份要按"是否正在贴底"抑制，抑制条件必须是任务状态而不是"存在贴底卡"这个布尔值，否则终态后清单会两处都看不见 |
| V4 | 目标横幅下移是纯位置调整 | **需复核**。`AgentGoalBanner` 在 `_buildAIPanel` 内，而 `_buildBottomBar` 是面板的兄弟节点（`Expanded(panel)` + `bottomBar`，[terminal_page.dart:841-842](../ai_terminal/lib/pages/terminal_page.dart#L841)）；横幅移到输入框之上要跨这两个节点，`ref.watch` 的宿主作用域（R3：按 hostId 取目标，不能用 activeHostId）必须原样带过去 |
| V5 | 移动布局共用同一套 | **需复核**。`_isMobile` 时底部条有 `padding.bottom + safe area`；贴底卡顺序变化后，键盘弹起的可见性要单独确认，不能假设 |

## 7. 不做清单

- 不复制参考图的深色配色/圆角尺寸（已有自己的 graphite-cyan 体系）。
- 不做 `@ 文件或对话`（本项目的上下文是服务器与会话，不是文件树）。
- 不做 `Default` 档位标签（模型配置里没有 tier 概念，硬造一个字段是假数据）。
- 不改会话流里操作单/时间线的既有结构。

**新阻塞**：app 连不上模型 —— 同一时刻 `curl` 用同一 key 打 `http://localhost:1994/v1/chat/completions` 返回 **200**，而 app 报 `连接失败: Unknown`（编辑对话框里点「测试」也是红色 `无法连接`）。所以问题在 app 侧的连接配置或错误翻译，不在这台机器的服务上。`agent_traces` 目录下没有落 trace 文件，暂时拿不到实际请求 URL。**下一步要么让用户在应用里看一眼 Base URL，要么从代码侧查 Dio 的 `Unknown` 是哪条路径抛的** —— 这条与面板布局无关，是独立问题。

### P3 第三轮（2026-11-01）：连接根因确认，但自动化输入被系统拒绝

**根因坐实**：`netstat` 显示服务只在 **IPv4** 上听（`0.0.0.0:1994`），`curl http://[::1]:1994/v1/models` 直接失败（000），而 `curl http://localhost:1994` 成功 —— curl 自己回退到 IPv4 了。把 Base URL 从 `localhost` 换成 **`127.0.0.1`** 后，app 编辑对话框里的「测试」显示 **`连接成功`**。所以 `连接失败: Unknown` 是 **Windows 上 `localhost` 解析到 `::1`、而本地服务没监听 IPv6** 造成的，Dio 把它归成 `unknown` 类型后错误文案只剩一句没用的 `Unknown`。

**这条值得单独修（与本文布局无关）**：本地端点用 `localhost` 时应该给出可执行的提示（"本地服务可能只监听 IPv4，把 localhost 换成 127.0.0.1"），而不是 `Unknown`。

**又一条自我更正**：中途截图出现整屏黑，我先怀疑 app 挂了。取 a11y 树后发现**界面完整**（`返回`/`连接管理`/`服务器列表` 全在）—— 是窗口最小化再恢复后**捕获帧失效**，不是应用问题。教训：黑屏先查 a11y 树再下结论。

**当前硬阻塞**：Computer Use 的输入通道被系统拒绝 —— `SetCursorPos failed: 拒绝访问 (0x80070005)`，随后 `target window could not be made foreground before native input`。截图仍可用，**只有点击/键盘进不去**，因为 `ai_terminal` 拿不到前台。
